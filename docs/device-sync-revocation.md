# 设备同步与撤销（2026-10-16）

对接后端 main `53c3954`，核对 docs/backend-api.md 第 16–20 节及 main、ChatHandler、UserHandler、WebSocket Worker/Dispatcher 的改动。

## API

- 握手头继续用 `deviceID`；发送、同步、ACK 的 JSON 字段不改名。
- `POST /user_devices`：本人查询发送 `{}`，指定用户发送 `target_user_id`。验证顶层目标及设备归属/active 状态，不领取预密钥。
- bundle / prekey 请求改用 `target_user_id`，兼容响应保留的 friend_id。仅首次会话需要领取，既有会话/缓存不重复消耗。
- `POST /revoke_device`：发送区分大小写的 `deviceID`、原值 password。200/202 都表示已撤销；websocket_closed=false 不表示撤销失败，不继续使用本机连接。

## 同账号消息

发送给好友时，查询好友设备和本人设备，排除本机。每台设备有独立会话与密文，共享逻辑 message_id。任一目标首次密钥准备失败时不提交整个发送批次；界面显示错误，避免无提示地漏掉同步设备。

好友收到普通正文；本人其他设备收到加密 JSON `chat.sent-copy.v1`（conversationId、messageId、text）。接收方先固定并验证发送设备属于本人，再解密及检查 messageId。副本显示到对应好友聊天、标记为本人发出的消息，不加入发件箱，不再次转发。协议解析失败不提交棘轮状态。设备间备注也通过此格式收发，入口在“我的设备”。双方均需升级此版客户端。

好友给本人所有活跃设备独立投递，因此收到的好友消息不通过本人设备再次转发。该流程不会迁移新设备注册以前的历史。缺少或过期 bundle、OPK 不足会阻止对应的新会话，需要在目标设备完成密钥准备。

## 撤销与凭据

“我的 → 我的设备与撤销”列出本人 active 设备，输入当前密码后确认撤销。其他设备 202 结果保留在当前页面的“关闭待确认”列表，可再次输入密码幂等重试；界面不宣称远端客户端已清除凭据。

本机撤销响应或当前连接的 Close(4001, device_revoked) 会停止聊天、刷新与重连，断开本地 socket，再删除内存和 Keychain 中的两种 Token。回调绑定连接代次和登录代次，迟到的关闭/刷新不能影响新登录。本机密钥标记不可用并保留；迟到的设备库写入不能恢复 registered 状态。不会自动删除私钥或历史，也不会静默生成替代设备身份。

删除凭据前持久化禁止自动恢复标记。删除失败仍退出内存会话，在当前进程有界重试，并在下次启动/登录前重试；失败期间不能恢复旧凭据。普通断线不登出。握手 403 停止自动重连并显示错误，不能仅凭没有明确原因的断线判断撤销。

后端尚未撤销设备关联的 Refresh Token/JWT，本地清理不是服务端 Token 失效保证。离线设备要在恢复运行并获知撤销后才能执行清理。

## 验证

模拟 HTTP 请求检查本人查询空对象、target_user_id、deviceID 与密码空格保留、202 解析；模拟 A1→Bob 与 A1→A2 独立加密，A2 正确归入 Bob 聊天且不产生转发；验证凭据删除失败阻止恢复、撤销中刷新不能恢复 Token、旧关闭不影响新登录，以及实际 RFC 6455 Close 4001 帧传递。

未对公网账号执行撤销或发送消息；真实多设备网络联调仍需进行。现有第三方 XEdDSA 编译警告保持未修改。
